这里的笔记都围绕一个问题：**怎么把大模型放进自己的工程里，而不是只会用聊天框。**

方向上分两块：一块是「模型跑在哪」（本地部署、量化、选型），一块是「模型怎么和你的数据、你的工具接起来」（MCP、RAG、上下文组织）。前者决定了成本和隐私边界，后者决定了它到底有没有用。

## 本分区笔记

- [本地大模型怎么选](./本地大模型怎么选.md) —— **什么时候该看这篇**：你要在自己机器上跑模型，但不确定该装 Ollama、LM Studio，还是直接用 llama.cpp / vLLM；或者已经跑起来了但显存不够、加载很慢。这篇给的是决策表，不是功能清单。

- [MCP 是什么](./MCP是什么.md) —— **什么时候该看这篇**：你想让自己的工具（查库、读文件、调内部接口）能被多个 AI 客户端复用，或者看到「MCP」这个词但搞不清它和 Function Calling 到底什么关系。含一个最小可跑的 TypeScript server。

- [RAG 最小可用实现](./RAG最小可用实现.md) —— **什么时候该看这篇**：你想让模型基于自己的文档回答问题，但不想先上一套向量数据库。这篇是一个零依赖的最小实现，重点在「切块怎么切」「为什么检索到了却答不对」。

- [提示词与上下文工程](./提示词与上下文工程.md) —— **什么时候该看这篇**：模型能跑、也能检索到资料，但输出不稳定、格式乱、还爱编。这篇讲的是上下文的组织方式，是前面几篇的「最后一公里」。

## 阅读顺序建议

如果是第一次搭：

```text
本地大模型怎么选  →  提示词与上下文工程  →  RAG 最小可用实现  →  MCP 是什么
   (跑起来)            (先会问)              (接上自己的数据)      (接上自己的工具)
```

如果只是临时查问题，直接按上面对应的「什么时候该看这篇」跳过去。

## 边界说明

- 本分区的笔记**以方向性结论和取舍为主**，具体版本号、参数名都尽量标了来源；**没有在本机验证过的内容都会显式标注「未验证」**。
- 这些技术迭代很快（尤其是本地推理的量化方案与 MCP 这类协议），看到命令报错时**先确认版本**，再怀疑结论。
